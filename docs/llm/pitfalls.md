# Known traps

Every item here has been verified against the code. Read the relevant section before editing.

## Blockers that prevent the pipeline from running

### Absolute paths to one machine

The string `/home/staff/enze/` appears 76 times across 45 files, in both `.sh` and `.py` files. It
points at the original author's account on one server. Examples:

- `/home/staff/enze/Front_DL3/script/parameters.py`, used to read every configuration value
- `/home/staff/enze/Front_DL3/pytorch-deeplab-xception/inference.py`
- `/home/staff/enze/Front_DL3/data_processing/cal_threshold.py`
- A hardcoded path to `ROI_new_ID.txt` inside `batch_preprocess_images/get_roi.py`

Nothing resolves paths relative to the script location. There is no path configuration mechanism
beyond `working_root`, `data_path`, and `codes_dir` in `para.ini`, and many scripts ignore those
and use the absolute path anyway.

Do not fix these one at a time. Substituting your own absolute path produces a second
machine-specific configuration that will break for the next person. Treat this as a design task.

### Scripts that are called but do not exist

Five come from the `FrontDL3/` submodule and three more from `downloads/enze/Front_DL3/`. Only two
remain unaccounted for, and both sit on commented-out call sites, so **every script on a live code
path is now available**. The full table is in `repository-map.md`. The pipeline still cannot run
from the root repository alone; it needs the submodule and the author's directory.

### The git layout is not the runtime layout

The operating procedure in `AutoTerm Pipeline.docx` requires manual file copying before anything
runs: helper scripts must be copied into a `data_processing/` directory created by hand inside
`Front_DL3/`, fourteen named Bash scripts must be moved there, every script called by
`batch_inference_plot_mv_figure_dir.sh` must be moved into `Front_DL3/`, and `~/.bashrc` must be
edited to put that directory on `PATH`.

The directory structure in git is the development layout. The scripts expect the deployment layout.
They are different.

### Required assets are not in the repository

| Asset | Example name | Where to get it |
|---|---|---|
| Trained checkpoint | `drn54_May5_2022_0.001_batch16_keep_augmentation.tar` | Obtained, at `downloads/`. 326 MB, mount it rather than baking it in |
| Bedrock and ice mask polygons | `bed_GID<n>_??.gmt` | **Still missing and the one hard blocker.** Absent from every archive in `downloads/`, including the author's own directory. `batch_truncate_termini.sh` hardcodes `bed_path=/home/staff/enze/data1/ice_mask/GIMP/crop_bed/buffer_15`. `downloads/Icemask.zip` is a possible derivation source, at the cost of a deviation |
| Per-glacier cutting polygons | `GID_<n>_cutting_polygon.gmt` | Generated by stage 2, sometimes drawn by hand. Only single-glacier samples are on disk |
| Flowlines | Per glacier | Not in git or any archive. Only needed by the commented-out flowline screening |
| Per-glacier `para.ini` | One per glacier | Generated by stage 2 |

Without a cutting polygon, stage 3 skips the glacier with a message and no error.

## Where the paper and the code disagree

The code is what runs. When they differ, follow the code and say so if you change it.

**During phase 1 reproduction work, do not change any of them.** The published dataset was produced
by this code, not by the paper's description of it, so these behaviours are what the reproduction
has to preserve. Correcting one changes the reference output that AutoTerm v2 will be measured
against. See `CLAUDE.md` at the repository root.

### Screening threshold coefficient

The paper states thresholds of `Q3 + 1.5 * IQR` and `Q1 - 1.5 * IQR`.

`data_processing/cal_threshold.py` computes `Q3 + 2 * (Q3 - Q1)`. The coefficient is 2, not 1.5, and
it returns only the upper bound.

`data_processing/cal_threshold_2.py` computes both bounds with the coefficient 1.5, matching the
paper.

Which one runs where:

| Metric | Script used | Coefficient | Bounds |
|---|---|---|---|
| Smoothness and complexity | `cal_threshold.py` | 2 | Upper only |
| Area change time series | `cal_threshold.py` | 2 | Upper only |
| Length | `cal_threshold_2.py` | 1.5 | Upper and lower |

The upper-only versus two-sided split matches the paper. The coefficient for the upper-only metrics
does not.

### Screening iteration counts

The paper says screening repeats up to 10 times or until no outliers are found.

`batch_inference_plot_mv_figure_dir.sh` runs two separate loops:

| Loop | Metrics | Maximum iterations | Early exit condition |
|---|---|---|---|
| One | Smoothness and length | 3 | Fewer than 15 newly abandoned traces |
| Two | Area change time series | 10 | Fewer than 1 newly abandoned trace |

Loop one stops at 3 iterations, not 10, and its early exit tolerates up to 14 remaining outliers
per pass rather than requiring zero.

### Flowline intersection screening is not active

The paper lists the number of intersections between trace and flowline as the first screening
metric, keeping only traces with exactly one intersection.

In `batch_inference_plot_mv_figure_dir.sh` the flowline screening loop is present but every line is
commented out. The two scripts it would call,
`batch_cal_flowline_proj_variation.sh` and `batch_abandon_results_proj_variation.sh`, are not in the
repository or the submodule.

Supporting Python does exist: `data_processing/calculate_flowline_intersection.py`,
`calculate_flowline_projection.py`, and `derivative_flowline_projection.py`. The Bash layer that
would drive them is what is missing.

### Early stopping patience

The paper reports early stopping after validation error is flat for 3 consecutive epochs.
`pytorch-deeplab-xception/train.py` defaults `--patience` to 5. The example invocations in
`FrontDL3/exe.sh` pass `--patience 5` and `--patience 4`.

### Learning rate and batch size have no defaults

The paper reports a learning rate of 2e-3 and batch size 16. In `train.py` both `--lr` and
`--batch-size` default to `None`. They must be passed explicitly. Passing neither does not fall
back to the published values.

`--weight-decay` defaults to 5e-4 and `--momentum` to 0.9, which do match the paper.

### Glacier count

The paper reports 295 glaciers. `GEE/Glacier_ID_list.txt` contains 290.

### A cloud filter is applied, though the paper says none is

Section 3.1 of the paper states plainly that no cloud filter is used, and gives the reason: cloud
fraction is computed over the whole scene, but the terminus occupies a small part of it, so a
heavily clouded scene may still show the terminus. Cloud affected results are supposed to be
removed later by the screening module.

The download scripts do filter on cloud cover at 60 percent:

| File | Line | Filter | Active |
|---|---|---|---|
| `GEE/batch_download_direct.py` | Sentinel-2 block | `ee.Filter.lt('CLOUDY_PIXEL_PERCENTAGE', 60)` | Yes |
| `GEE/batch_download_direct.py` | Landsat blocks | `filterMetadata('CLOUD_COVER', 'less_than', 60)` | No, commented out along with the rest of the Landsat blocks |
| `GEE/batch_download.py` | Landsat block | `filterMetadata('CLOUD_COVER', 'less_than', 60)` | Yes |
| `GEE/batch_download.py` | Sentinel-2 block | `ee.Filter.lt('CLOUDY_PIXEL_PERCENTAGE', 60)` | Yes |

Removing the filter increases the download volume substantially. Do not remove it to match the
paper without asking first.

### Sensor names have two incompatible spellings

Directory and file names use `Landsat-5`, `Landsat-7`, `Landsat-8`, `Sentinel-1_A`, `Sentinel-1_D`,
and `Sentinel-2`.

`merge_shp/get_uncertainty.py` matches on `Landsat5`, `Landsat7`, `Landsat8`, `Sentinel1`, and
`Sentinel2`, with no hyphen and no ascending or descending suffix. Passing the directory spelling
falls through to the else branch, which prints `N/A` and then calls `os._exit()` with no argument.
`os._exit()` requires a status argument, so this raises `TypeError` rather than exiting.

### Zero means missing in the uncertainty table

`get_uncertainty.py` treats a zero uncertainty as absent data and substitutes the other measure, or
the string `N/A` if both are zero. A real uncertainty of zero cannot be expressed. Code that writes
into `uncertainty_all_lola.txt` must leave gaps as zero, and code that reads it must not treat zero
as a measurement.

### Sensor selection is a manual comment-and-uncomment toggle

`GEE/batch_download_direct.py` never downloads all five sensors in one run. The author selected
sensors by commenting out the blocks not wanted, and committed whichever state the last run used.
This is a working pattern, not a defect, and it is confirmed by comparing two versions of the file:

| Version | Landsat 5 | Landsat 7 | Landsat 8 | Sentinel-1 A and D | Sentinel-2 | Lines |
|---|---|---|---|---|---|---|
| Published, commit `cab8265`, in `downloads/AutoTerm.zip` | Absent | Absent | Active | Commented out | Commented out | 151 |
| Current working tree, commit `f1df8ca` | Commented out | Commented out | Commented out | Active | Active | 313 |

The later commit added the Landsat 5 and Landsat 7 blocks and flipped which set is enabled. The two
versions are near inverses of each other.

Consequences for reproduction:

1. Running the file as committed fetches only Sentinel-1 and Sentinel-2.
2. Reproducing the full five-sensor dataset requires editing this file between runs, or running it
   more than once with different blocks enabled. Doing so is expected and is not the kind of source
   change the minimal-modification rule is meant to prevent.
3. `GEE/batch_download.py`, the Google Drive export variant, has its Landsat block active and is the
   script that currently reflects the multi-sensor design.

### The Zenodo code archive contains nothing this repository lacks

`downloads/AutoTerm.zip` is the published code archive, doi:10.5281/zenodo.8270875. Verified against
the working tree:

1. It is a GitHub snapshot of this repository at commit `cab8265`, an ancestor of current HEAD.
2. Zero files in it are absent from this repository.
3. None of the ten scripts the pipeline calls but does not ship are in it, including
   `gdal_merge_average.py`, `rm_small_polygon.py`, and `point_in_polygon.py`. The published archive
   was never self-contained.
4. The only content difference is `GEE/batch_download_direct.py`, described above.

Do not search this archive again for missing scripts. The data archive, doi:10.5281/zenodo.7782039,
is separate and has not been checked; it is the remaining candidate for the checkpoint and the
polygon assets.

## Code-level traps

### pixel_overlay is not a stride

In `pytorch-deeplab-xception/split_image.py`, the function `sliding_window` places patches on a
non-overlapping grid of step `patch_w`, then extends each patch outward by `adj_overlay_x` on both
sides:

```
xoff  = max(i * patch_w - adj_overlay_x, 0)
xsize = min(i * patch_w + w + adj_overlay_x, image_width) - xoff
```

An interior patch is therefore `patch_w + 2 * adj_overlay_x` pixels wide, not `patch_w`.

With the committed inference values, `inf_patch_width=192` and `inf_pixel_overlay_x=384`, an
interior patch is up to 960 pixels wide, which is why `crop_width` is 960. Reading
`inf_pixel_overlay_x` as a stride gives a patch count that is wrong by a large factor.

The same file contains `sliding_window_test`, which uses Python 2 integer division
(`int(image_width)/int(patch_w)` without `//`) and produces floats on Python 3.

### Reversing a trace before closing a polygon

Area between two traces is computed by concatenating them into one closed ring. Both traces are
open polylines running in the same direction, so one must be reversed first. That is what
`data_processing/invert_data2.py` is for.

Code that concatenates two traces without reversing one produces a self-intersecting figure and a
meaningless area. This applies to the error metric, the MC dropout uncertainty, the duplicate trace
uncertainty, and the area change screening metric.

### np.loadtxt on trace files is unforgiving

`.gmt` trace files are read with `np.loadtxt` and must contain nothing but two numeric columns. A
header, a comment, or a multi-segment separator raises rather than parses. `exe_inference.sh`
strips the `ogr2ogr` header with `sed -i 1,11d`, a fixed line count. If a future GDAL version writes
a header of a different length, this silently removes data rows or leaves header lines behind.

### Python 2 and Python 3 are mixed

There are 13 call sites invoking `python2 parameters.py` in the root repository's shell scripts.
`parameters.py` itself is Python 3 clean; the interpreter name is stale. The common workaround is a
`python2` symlink pointing at `python3`, which is what `Dockerfile.frontdl3` does.

Two files are genuinely Python 2 only and will fail to import on Python 3:

| File | Python 2 only import |
|---|---|
| `pytorch-deeplab-xception/basic_src/basic.py` | `commands` |
| `pytorch-deeplab-xception/basic_src/DemConvert.py` | `HTMLParser` |

`pyproject.toml` declares `requires-python = ">=3.10"`.

### Modern PyTorch rejects the 2022 checkpoint

PyTorch 2.6 and later default `torch.load` to `weights_only=True`, which refuses the published
checkpoint. Set `TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD=1`, as `Dockerfile.frontdl3` does.

### Dataloader workers re-run the inference script

`inference.py` is a bare script with no `if __name__ == "__main__":` guard. Under Python 3.14's
default forkserver start method, a dataloader worker re-imports the module and re-executes it. Both
the root copy's `exe_inference.sh` and the submodule fork pass `--workers 0` to avoid this. Do not
raise the worker count without adding a main guard.

### Removed and renamed third-party APIs

| Call | Problem |
|---|---|
| `from scipy.ndimage import imread` in `datasetRS_Mar15.py` | Removed in scipy 1.3. The import is unused; deleting the line is safe |
| Tab-indented line 38 of `utils/lr_scheduler.py` | Python 3 raises TabError. `inference.py` imports this transitively |

Both are already fixed in the `FrontDL3/` submodule fork.

### GPU assumptions

`pytorch-deeplab-xception/inference.py` in the root copy calls `x.cuda()` unconditionally. There is
no CPU path.

`exe_inference.sh` sets `export CUDA_VISIBLE_DEVICES=0` in the root copy. Upstream FrontDL3 set it
to `1`, the author's second GPU.

The `FrontDL3/` submodule fork makes `--cuda` optional. Use the submodule when you need to run
inference without a GPU.

### Committed build artifacts

`*.pyc` files and `__pycache__/` directories from Python 3.6 and 3.8 are committed throughout
`pytorch-deeplab-xception/`. There is no `.gitignore`. A stale `.pyc` can shadow a source file you
edited. `FrontDL3/script/split_image.pyc` is one such file.

### No tests, no CI, no dependency manifest

`pyproject.toml` has an empty `dependencies` list and packages only `autoterm`, which is a stub.
The root `Dockerfile` is zero bytes. There is no test suite and no continuous integration.

The consequence for an agent: there is no automated way to detect that a change broke something.
`running-and-verifying.md` describes the manual checks that are available.
